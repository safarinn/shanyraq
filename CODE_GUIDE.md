# Как понять и защитить Shanyraq.kz

## В каком порядке читать код

1. `public/register.html` — обычная форма с полями и кнопкой.
2. `public/js/auth.js` — что происходит при нажатии «Зарегистрироваться».
3. `public/js/common.js` → функция `request()` — как данные отправляются серверу.
4. `server.py` → блок `/api/register` — проверка данных и сохранение пользователя.
5. `schema.sql` → таблица `users` — где пользователь хранится.
6. `public/catalog.html` и `public/js/catalog.js` — карточки и поиск.
7. `public/css/style.css` — оформление и Flexbox.

HTML больше не создаётся целыми страницами внутри JavaScript. Открой HTML нужной страницы: формы, таблицы, меню и основные блоки находятся прямо там.

## Один пример: регистрация

В `register.html` поле выглядит так:

```html
<input name="email" type="email" required>
```

- `name` — название поля, по которому JavaScript читает значение.
- `type="email"` — браузер проверяет формат email.
- `required` — поле нельзя оставить пустым.

В `auth.js`:

```javascript
form.addEventListener('submit', async function (event) {
  event.preventDefault();
  // Читаем поля, проверяем их, отправляем серверу.
});
```

`addEventListener` ждёт событие. `submit` — отправка формы. `preventDefault()` отменяет стандартную перезагрузку страницы. `async` позволяет использовать `await` — дождаться ответа сервера.

```javascript
await request('register', data);
location.href = 'index.html';
```

Сначала отправляем объект `data` на сервер. Если регистрация успешна, открываем главную. Если сервер вернул ошибку, `catch` показывает её рядом с формой.

## Как работают карточки

В `catalog.html` есть `<template id="property-template">`. Это образец одной карточки, который сам по себе не виден на странице.

`common.js` → `displayProperties()`:

1. Берёт этот образец.
2. Копирует его для каждого объявления через `cloneNode(true)`.
3. Заполняет цену, название, адрес и характеристики через `textContent`.
4. Вставляет карточку в список через `appendChild()`.

`textContent` вставляет именно текст. Пользовательское название не может превратиться в исполняемый HTML.

## Как работают фильтры

`catalog.js` → `filterProperties()` читает выбранный город, тип, максимальную цену и поисковый текст. Обычный цикл `for...of` проверяет каждый объект. Если он не подходит, `continue` переходит к следующему. Подходящие объекты добавляются в массив `results`.

`sort()` меняет порядок результатов. Функция `a.price - b.price` сортирует от дешёвых к дорогим; `b.price - a.price` — наоборот.

## Flexbox вместо Grid

В CSS нет `display: grid`, `grid-template-columns` или `grid-column`.

```css
.property-list {
  display: flex;
  flex-wrap: wrap;
  gap: 20px 2%;
}
.card {
  width: 32%;
}
```

- `display: flex` ставит карточки в ряд.
- `flex-wrap: wrap` переносит их на следующую строку.
- `gap` задаёт расстояние: 20 px между рядами и 2% между карточками.
- Три карточки по 32% и два промежутка по 2% занимают 100% строки.

На планшете карточка имеет ширину 49%, на телефоне — 100%. Эти изменения находятся в `@media`.

**Отличие от исходного задания:** в документе перечислен CSS Grid. В этой версии он намеренно заменён Flexbox по просьбе пользователя. Остальные функции сохранены.

## Зачем сервер и база

HTML/CSS/JS показывают интерфейс в браузере. Python сохраняет данные в SQLite. Поэтому аккаунт, избранное и заявки сохраняются после обновления страницы и перезапуска сервера.

| Таблица | Что хранит |
|---|---|
| `users` | Аккаунты, имя, email, хеш пароля, телефон и роль. |
| `properties` | Объявления недвижимости. |
| `favorites` | Связь пользователя с сохранённым объявлением. |
| `bookings` | Записи на просмотр, дату, время, телефон, статус. |

SQL `?` — место для значения. Значения передаются отдельно от текста SQL: это защищает от SQL-инъекций.

## Основные слова для защиты

| Термин | Значение в этом проекте |
|---|---|
| DOM | HTML-элементы страницы, которыми управляет JavaScript. |
| Event | Действие пользователя: клик, ввод текста, отправка формы. |
| fetch | Отправка HTTP-запроса из браузера на сервер. |
| JSON | Формат передачи данных между JavaScript и Python. |
| API | Адреса `/api/...`, через которые браузер обращается к серверу. |
| GET | Получить данные. |
| POST | Отправить данные или выполнить изменение. |
| CRUD | Create, Read, Update, Delete: добавить, посмотреть, изменить, удалить. |
| Session | Сервер помнит, какой пользователь вошёл. |
| Cookie | Браузер хранит случайный номер сессии и отправляет его серверу. |
| CSRF token | Дополнительный токен проверки изменяющих запросов. |
| Hash | Пароль преобразуется в проверочное значение; исходный пароль не хранится. |

## Короткое объяснение проекта преподавателю

«Я сделал многостраничный сайт недвижимости. HTML отвечает за структуру, CSS и Flexbox — за оформление и адаптивность, JavaScript — за формы, события, поиск и динамические карточки. Сервер Python обрабатывает запросы и сохраняет данные в SQLite. Пользователь может зарегистрироваться, сохранить объявления и записаться на просмотр. Администратор управляет объявлениями и статусами заявок».
